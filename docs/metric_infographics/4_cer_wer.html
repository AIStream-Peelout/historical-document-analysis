How many edits away?

Character error rate is the HTR community's standard number, and we keep it so our results can be read against everyone else's. But never as a bare mean: an edit count only means something once you know the output was an attempt at this page, in this order. Everything below is about what has to be true before the number is worth quoting.

1

Normalise both sides

All whitespace collapses to single spaces, both strings are put into Unicode NFC, and that is the whole of it — no case folding, no punctuation stripping, nothing that would make one system's conventions cheaper than another's. Same fragment as page 1: a line from a Judaeo-Aramaic marriage contract (Oxford, Bodleian MS heb. a 2/4), where the model has misread one letter and closed with a stock blessing that is not on the page.

2

Count the cheapest edit path

Levenshtein distance: the smallest number of single-character insertions, deletions and substitutions that turns the output into the reference. Here the cheapest path is one substitution and one long deletion.

12 edits. Insertions would count the same way — the model dropped nothing here, so there are none.

3

Divide by the reference length

0.4112 edits ÷ 29 reference characters

The denominator is the page, not the output. Eleven of these twelve edits are text the model added, and the page it was added to is what they are divided by — so writing extra raises CER without any ceiling. That asymmetry is not a defect to be patched out; it is the property that makes step 6 readable.

metrics.py · cer_levenshtein, cer_pair

Words instead of characters

The identical computation with whitespace-delimited words as the units. Three of the output's seven words are edits against the reference's five.

WER is harsher on Hebrew than on Latin-script transcription, because one wrong letter is a whole wrong word: the single כ for ב that cost 1 of 29 characters costs 1 of 5 words. We report WER alongside CER, but read CER first.

5

Strict versus lenient

Some references carry vowel points and cantillation; most model outputs do not. Strict CER scores the text as written. Lenient CER decomposes both sides with NFKD and drops every combining mark, keeping the base letters, then scores that. On a pointed reference the difference is the whole score.

Reference, pointedבְּנַחְשָׁא טָבָא17 code points
Output, unpointedבנחשא טבא9 code points
0.47strict — 8 deletions ÷ 17, although every letter is right
0.00lenient — marks stripped from both sides

The benchmark reports both for every output. They mostly agree: on this benchmark 151 of 1,352 paper-system outputs differ by more than 0.01 between the two, and those are exactly the pointed-reference pages where the choice matters.

metrics.py · strip_nikud (NFKD, drop U+0591–U+05C7 combining marks)
6

Not clamped

An output can be arbitrarily longer than the page, so CER can exceed 1. We do not cap it. When a decoder falls into a loop and runs to the token limit, the size of the overshoot is the finding — capping it at 1.00 would file that run next to a polite refusal.

7

Conditional, never bare

What the paper actually prints is CER*: the median CER over substantive attempts only — outputs that got past the abstention, loop and hallucination gates of page 2 — and read only on Tier A fragments, where two independent readers agreed the editor transcribed the right layer in the right order (page 5). Why it is never quoted bare

Three things an edit count will not tell you on its own

1.00 = 2.69 = 0.69?a refusal, a loop, and an accurate reading of a third of the page

CER ranks the loop as the worst of the three and the refusal as better than the partial read. Only the partial read touched the ink. An error rate orders outputs by distance, not by whether anything was read.

Median conditional CER of raw Kraken lines at submission, the best figure in the paper, and of HebVL-2.1 a month later, the current best. Both are the standard HTR definition, so they compare directly with published MiDRASH numbers.

What it does not see

A distance to one transcription, and only that

It depends on a single linearisation of the page. On multi-layer fragments — marginalia, over-writing, a palimpsest under-text — there is no one correct order for the editor to have chosen, so a correct reading in a different order pays for the difference. That is why Tier B CER is never reported as a headline.
It conflates completeness and accuracy. Reading half the page perfectly and reading all of it badly can land on the same number. Page 3 of this series separates the two, which is the only way to tell those two systems apart.
One letter wrong is one edit, whatever kind of wrong it is. A plausible palaeographic confusion (ב for כ) and an invented character cost exactly the same. Error types are counted by the judge taxonomy, not here.
Lenient CER is the fairer comparison, and strict is kept anyway. For models that add or drop pointing, lenient is the number to read. Strict stays because some references are pointed, and a model that hallucinates nikud onto an unpointed page should pay for it.
