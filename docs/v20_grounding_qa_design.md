# v20 grounding + QA task design (draft 2026-08-30)

Supervision source: KTIV API-shape bundles — word-level boxes + sigla per
annotation, line/column structure recovered by `ktiv_layout.reconstruct_page`
(post mash-fix). Verified stock: ~88k word boxes in the new-candidate pool,
~500k+ across the v1.9a-train manuscripts, growing with the DOM re-scrape.

## Conventions (locked by the 2026-08-28/30 probes)

- Coordinates: `[x0, y0, x1, y1]` ints, **0–1000 normalized to the original
  scan frame** (KTIV's geometry frame). Normalized coords survive processor
  resizing, so the original→served frame transform disappears. v19a already
  natively answers in this convention (probe: 12/12 JSON boxes, 8/12
  center-hits normalized vs 2/12 absolute).
- Answer container: `{"bbox_2d": [...]}` / arrays of `{"text", "bbox_2d"}` —
  the Qwen-native key the model already emits.
- Page eligibility: geometry mode only (`rec["mode"] == "geometry"`); skip
  served-breakline pages (no trustworthy boxes), degenerate boxes, and
  deep-overlap words (interlinear insertions, per `OVERLAP_MERGE_FLOOR`).

## Task families (target ~5–10% of the v20 mixture combined)

1. **locate** — phrase → box. Sample 2–4 consecutive words on one line, all
   with ≥2 Hebrew letters, no gap tokens, phrase letters **unique on the
   page** (substring count == 1); target = union of word boxes. Grounding is
   activation-not-teaching for this model, so a modest share suffices.
2. **read_box** — box → text. Line-level (line box slightly padded → line
   text). Teaches region-conditioned reading; the building block for a
   "transcribe this region" API. Variant: multi-line column slice.
3. **grounded transcription** — page → JSON array of `{text, bbox_2d}` per
   line, reading order preserved. The high-value format: it makes the core
   transcription task grounded, and at inference time yields boxes for free
   on untranscribed corpora (the "pull boxes from what it transcribes"
   path). GT comes straight from `reconstruct_page` lines. Risk to manage:
   JSON-wrapped output must not bleed into the plain-transcription format —
   distinct prompt, and keep the share small (~2-3%).
4. **layout QA** (small share) — questions answerable from pixels with
   GT-derivable answers: "How many columns?", "Transcribe only the first
   line of the left column", "Which line contains ‹phrase›? Return its text".
   These are templated from reconstruction structure — no LLM generation
   needed, zero hallucination risk in targets.

Open (phase-2, not v20-blocking): free-form content QA generated by a large
text LLM from GT transcriptions (needs generation + verification pass);
alignment-based pseudo-grounding for corpora without word boxes (align model
transcription lines to Kraken segmentation boxes — works even where KTIV-style
supervision doesn't exist, e.g. PGP/HebrewBooks self-training).

## Eval (built 2026-08-30, `grounding_eval.jsonl`, 133 queries / 24 pages)

Clean religious-benchmark pages (decontaminated, geometry-verified): 72
locate (phrase-level IoU + center-hit; chance ≈ 2–4%), 37 read_box (CER,
length-ratio), 24 grounded pages (parse rate, line-match rate, line IoU/CER).
Baseline numbers for stock v19a pending (run queued behind the merger-probe
benchmarks). These 133 queries double as the held-out grounding eval for v20.

## Builder changes (`build_ktiv_dataset.py`)

- Emit the three row types alongside page/region transcription rows, gated by
  the eligibility rules above; grounding rows only from train-pool mss (same
  decontam gates as transcription rows).
- Region-crop tasks and locate targets must share one frame: normalize by the
  ORIGINAL page dims for full-page tasks; for crop rows re-normalize to the
  crop frame (or skip grounding rows on crops in v20 — simpler).
- Per-row provenance: task name in the existing `task` column
  (`locate` / `read_box` / `grounded_page` / `layout_qa`).
